36 文件恢复复盘

事故复盘 · 2026-10-30 · AgentSwarm 仓 · 真相源 docs/generated/teamwork-snapshot.md

发生了什么

2026-10-30，AgentSwarm 仓 36 个 tracked 文件从磁盘消失。归因走「跨会话询问与回执协议」：herdr agent prompt 双发两个并行会话（wR:p1A DIST / wR:p15 PYST），要求各席位按五点自证回执 —— ①操作面清单 ②是否我方 ③可查证据 ④本会话执行过的 git 危险命令 ⑤内容归属核对。

处置过程

  1. p1A 回执「②非我」入档（commit 6e3a3d567a）：32 件路径与我操作面交集 0，执行过的删除仅三类且均有据可查。
  2. 按回执方案② git checkout -- 恢复，我方不恢复、不 add -A。
  3. 01:06:35 全部 36 件恢复；staged 1368→0（1364 = conflicts/ 生成物取消跟踪被撤）。
  4. origin/HEAD 全程零损。

关联事件：310b 回退

同周期 310b 事故：无路径参数 commit 吃整个 index，index 是陈旧工作树，496 文件被回退。恢复方法论 = blob 三方比对（好基线 / 坏提交 / origin 现状）精确提取受害集，commit 1e6b758565 外科恢复到 fadd 版，fsm.py PR#605 dryrun 守卫 + 17 测试全过，已推 origin behind=0。

五点自证（制度产物）

跨会话询问回执机制自本次事件启用，全文见 multisessions 技能「跨会话询问与回执协议」。遗留：「谁删的」无认领者（32 件全属他线）—— 再发同类事件按五点自证追责；p1A 措辞（我方不恢复）与行为（同分钟恢复）不一致，已记档为下轮追问点。

经验固化

  1. 多会话共享工作区禁止无路径参数 commit（310b 根因，吃整个 index）
  2. 删除前逐件对 DB + 工作区 + 并行注册表核对，不按提交来源一刀切
  3. 归因靠协议回执，不靠猜测；回执必须可查证（路径交集、命令清单）

治理实战 · 2026-10-19→2026-11-01 · OriginForce+OriginFlow · 真相源 OriginForce/docs/neo-machine-digital-company-plan-v1.md

经验固化

  1. 契约（schema）与投影必须有机器可验的等价检查，否则漂移静默累积
  2. 「schema 为准」的裁决规则消除了双向修改的死循环
  3. 检测器复用为生成器的验收测试 —— 同一逻辑源 schema_common.py

桥从零到通

集成实战 · 2026-10-31 · OriginFlow S3b · 真相源 scripts/zs_feishu_bridge.sh + teamwork 决策日志

目标

ZenSwarm 执行流水自动进飞书：轮询 ZS git log（task done/fail/create 事件）→ 群「NeoMachine 执行流水线」播报 + Base 任务流水状态 upsert。人在飞书侧看到每一件任务的生死。

从零到通的坑

  1. git --since=@0 invalid —— @0 不是合法 epoch 表达，需实际 epoch 数值。
  2. state 文件存增量 ts，取值必须 ts+1 防同秒重复播报。
  3. best-effort 单工设计：桥挂了 ZS 不依赖飞书，执行层零耦合。

打通状态

2026-10-31 启用：state = .team/bus-bridge.state；历史 197 任务已入 Base 任务流水（200 行含 probe/form 遗留），群已播报 50+；timer 5min 常驻。当前最近同步 11-01 01:30，群 chat_id oc_868c…aa009。

派工约定

herdr pane 敲 zenswarm zen @<席位> <task-id> → done 事件自动入群 + Base。

经验固化

  1. 跨系统集成先定单工方向：执行层不依赖展示层
  2. 增量游标（state ts）是轮询桥的最小可靠性单元，+1 处理边界
  3. 历史数据回灌（197 任务）与增量播报分开跑，避免首跑风暴
